📦 Estrutura de Funcionamento — Integração myCUBI ↔ MaxData API

Documento de referência técnica — Baseado na integração implementada e em funcionamento na Central Peças (ROLAMENTOS-8719).
Pode ser usado como base para novas integrações com outros clientes que também usam MaxData.

1. Visão Geral

A integração conecta a balança volumétrica myCUBI-50 ao ERP MaxData, permitindo que, ao pesar e medir um produto na balança, as dimensões e peso sejam automaticamente gravados no cadastro do produto dentro do MaxData.

┌─────────────────┐     HTTP (PUT)     ┌──────────────────────┐     HTTP (REST)     ┌────────────────────┐
│  Balança myCUBI │ ──────────────────▶│  INTEGRADORA (Node)  │ ───────────────────▶│   API MaxData      │
│   (aparelho)    │                   │  rodando na máquina  │                    │ rds.skytins.com.br │
└─────────────────┘                   └──────────────────────┘                    └────────────────────┘

2. Componentes da Integração

2.1 A Integradora (middleware local)

É um servidor HTTP local feito em Node.js + Express, instalado em uma máquina da rede do cliente. Ela funciona como "ponte" entre o myCUBI e a API do MaxData.

  • Linguagem: Node.js (v18+)
  • Framework: Express
  • Porta padrão: 3000
  • Roda como: processo Node no Windows (via cmd ou como serviço)

3. Pré-requisitos de Rede

✅ Resposta à dúvida: Precisa estar na mesma rede?
ConexãoRequisito de rede
myCUBI ↔ Integradora✅ SIM — precisam estar na mesma rede local (LAN). A balança acessa a integradora pelo IP local da máquina.
Integradora ↔ API MaxData🌐 Apenas acesso à internet (ou VPN/rede do servidor MaxData). A API fica em rds.skytins.com.br:8720.
myCUBI precisa de internet?❌ NÃO — ela só precisa "ver" a integradora na rede local. É a integradora que fala com a internet.
Resumo prático: A integradora pode ser instalada em qualquer máquina que:
1. Esteja na mesma rede local da balança myCUBI.
2. Tenha saída para internet (ou acesso ao servidor MaxData via VPN).

4. Fluxo Completo de uma Medição

1. Operador pesou/mediu o produto na balança myCUBI
       │
       ▼
2. myCUBI faz chamada HTTP:
   PUT http://{IP_DA_INTEGRADORA}:3000/products/{EAN}/measurement
   Header: X-API-Key: {chave-configurada}
   Body: { width, height, depth, weight, weightType }
       │
       ▼
3. Integradora valida a API Key (segurança)
       │
       ▼
4. Integradora autentica no MaxData:
   POST http://rds.skytins.com.br:8720/v2/auth
   Body: { empId: 1, terminal: "364F64E6539974C1D75C8A46C14B2D3D" }
   Resposta: { token: "JWT...", expiration: "..." }
       │
       ▼
5. Integradora busca o produto no MaxData pelo EAN:
   GET http://rds.skytins.com.br:8720/v2/product?barCode={EAN}&empId=1
   Header: Authorization: Bearer {token}
       │
       ▼
6. Converte unidades (myCUBI envia em mm e g → MaxData espera cm e kg)
       │
       ▼
7. Integradora atualiza as medidas no MaxData:
   PUT http://rds.skytins.com.br:8720/v2/product/measures/{id_produto}
   Body: { empId, width, height, depth, grossWeight }
       │
       ▼
8. Integradora responde ao myCUBI:
   HTTP 200 — { done: true, data: null, flag: null }

5. Autenticação — Dois Níveis

5.1 myCUBI → Integradora (API Key fixa)

A balança envia uma chave fixa no header de cada requisição:

X-API-Key: central-pecas-2026
  • Essa chave é configurada no .env da integradora
  • A mesma chave deve ser registrada no painel de configuração do myCUBI
  • Não expira — é uma string fixa definida pelo instalador

5.2 Integradora → MaxData (JWT com auto-refresh)

O MaxData usa JWT (JSON Web Token) com expiração:

  • A integradora autentica via POST /auth com empId + terminal
  • O token retornado tem uma data de expiração informada na resposta
  • A integradora mantém o token em cache em memória
  • Antes de cada requisição, verifica se o token ainda é válido
  • Se faltarem menos de 60 segundos para vencer, renova automaticamente
  • Se receber um erro 401, invalida o cache e renova imediatamente
  • Não é necessária nenhuma intervenção manual — tudo é automático

6. O Terminal MaxData — O que é e como obter

O que é o Terminal?

O terminal é um identificador hexadecimal que representa uma "estação" cadastrada no MAX-Manager do cliente. A API MaxData exige esse terminal para autenticar — cada máquina/integração deve usar um terminal cadastrado.

Como foi obtido na Central Peças

O terminal da integração da Central Peças foi fornecido pelo técnico do suporte MaxData, que identificou o terminal vinculado à máquina ROLAMENTOS-8719 no MAX-Manager.

Terminal: 364F64E6539974C1D75C8A46C14B2D3D

Como obter para um novo cliente

  1. Pedir ao técnico MaxData — informar o nome da máquina (hostname) e pedir o terminal cadastrado no MAX-Manager
  2. Acessar o MAX-Manager diretamente → menu Terminais
  3. Via Swagger da API → GET /terminal (se disponível)
    Swagger: http://rds.skytins.com.br:8720/swagger/index.html
    Usuário: maxdata | Senha: max5699
⚠️ Importante: Cada cliente/empresa tem seus próprios terminais. O terminal 364F64E6539974C1D75C8A46C14B2D3D é exclusivo da Central Peças e não deve ser reutilizado em outro cliente.

7. Configuração da Integradora (arquivo .env)

# Porta onde a integradora vai escutar
PORT=3000

# Chave de API fixa — configurar o MESMO valor no painel do myCUBI
MYCUBI_API_KEY=central-pecas-2026

# MaxData — dados fornecidos pelo suporte MaxData ou MAX-Manager
MAXDATA_BASE_URL=http://rds.skytins.com.br:8720/v2
MAXDATA_EMP_ID=1
MAXDATA_TERMINAL=364F64E6539974C1D75C8A46C14B2D3D

# Conversão de unidades (myCUBI envia mm/g → MaxData espera cm/kg)
UNIT_DIMENSION=cm
UNIT_WEIGHT=kg

# Nível de log (debug | info | warn | error)
LOG_LEVEL=info

10. Instalação Resumida (Windows)

  1. Instalar Node.js na máquina (versão 18 ou superior)
  2. Copiar a pasta mycubi-maxdata-integrator para a máquina
  3. Editar o arquivo .env com os dados do cliente
  4. Abrir cmd na pasta do projeto e rodar: 
    npm install
node src/index.js
  5. Testar: abrir navegador e acessar http://127.0.0.1:3000/health
  6. Configurar no myCUBI o IP da máquina + porta 3000 + API Key
